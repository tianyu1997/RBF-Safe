# RBF-Safe 项目阅读路线（v5.0）

> 维护依据：[英文文档总索引](../../README.md)

RBF-Safe v5.0 的模块跨度较大，不建议按文件名逐个阅读。更有效的顺序是：先理解安全语义，再跑通最小认证闭环，然后按版本演进阅读规划、策略安全、安全记忆和分布式信任模块。

阅读一个模块时，统一采用以下顺序：

```text
概念文档
  → 公共头文件
  → 核心 .cpp
  → 对应 test_*.cpp
  → quickstart 示例
  → 持久化格式文档
```

测试通常比内部辅助代码更容易说明边界行为。`src/internal/`、`json.cpp`、`sha256.cpp` 和各类 `*_persistence.cpp` 应放在对应公共 API 之后阅读。

## 第一阶段：建立全局认识

依次阅读：

1. [中文 README](../../../README.zh-CN.md)：了解项目定位、主要能力和构建入口；
2. [中文文档索引](../README.md)：建立文档地图；
3. [安全模型](../../core/safety-model.md)：理解证据等级、身份绑定和失败关闭；
4. [体系结构](../../core/architecture.md)：理解模块依赖和数据流；
5. [API 总览](../../core/api.md)：了解公共类型分别负责什么；
6. [路线图](../../maintenance/roadmap.md)：了解 v0.1 至 v5.0 的功能演进。

这一阶段最重要的问题是：RBF-Safe 认证什么、不认证什么，以及一个成功返回值最多能表达哪一级证据。

不要跳过安全模型。几何认证、规划成功、采样回归、签名有效和硬件执行安全是不同层次的结论。

## 建议的阅读深度

### 快速掌握核心

如果只想先掌握约 80% 的核心思想，完成以下内容即可：

1. 第一阶段全部文档；
2. 几何、LECT 和 SafeAtlas 主链路；
3. 轨迹审核；
4. 动态更新；
5. 运行时 Shield；
6. SafetyMemory 与 SafetyMemoryStore。

### 准备修改核心认证算法

继续深入：

- `src/internal/` 中与几何、Atlas 和身份有关的辅助实现；
- 所有 `test_geometry`、`test_atlas`、`test_golden` 和持久化损坏测试；
- 固定 fixtures 与 release benchmark；
- `data/api_surface_v5.sha256` 和项目范围清单。

### 准备开发集成或部署功能

重点阅读：

- OMPL、MoveIt 2、Safe IK 和规划消费者；
- shield、策略门禁和校准生命周期；
- identity、deployment、execution、trust 和 provenance；
- 对应格式文档、资源上限、取消及失败关闭测试。

无论阅读到哪个阶段，都应将公共头文件中的声明、英文安全契约和测试行为视为同一功能的三个组成部分，不能只根据单个 `.cpp` 推断 API 或安全保证。
